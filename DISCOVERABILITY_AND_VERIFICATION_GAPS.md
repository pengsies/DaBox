# RelayForge Discoverability and Verification Gaps

This audit is based on the current workspace source and local tests. No request was sent to the EC2 host. “Source-confirmed” does not mean deployed or remotely reachable.

| Area | Current evidence / gap | Smallest fair fix | Impact |
|---|---|---|---|
| Initial credentials | The only seeded account is `guest`; its password is `guest-relay-2026` in organizer-side `db/init/002-schema.sql.in`. No public route reveals either value or a password hash. Login has 8 requests/minute plus burst 4, and failed attempts sleep 0.35s. The pre-auth CSRF session is not marked permanent by `login_view`; do not assume the configured 30-minute lifetime applies to it. | For true IP-only play, serve a per-deployment salted credential hash and username as an intentional public challenge artifact, or expose a small clue that sharply bounds a known offline wordlist. Publish its format/tool parameters. Do not call unrestricted online Hydra guessing a realistic credential-recovery mechanism. | Critical. A player cannot reliably enter the portal with only the IP and generic local wordlists; a large candidate space is prohibitively slow. |
| Hydra assumptions | `hydra` requires both username and password candidates. Login GET and POST share Nginx's `/login` limit; the form requires a CSRF value and session cookie. The successful session is configured permanent for 30 minutes, but the pre-auth session used during guessing is not marked permanent by `login_view`. | If online guessing is the intended mechanic, provide a bounded username/password space and test whether the installed Hydra version reuses the captured CSRF/session correctly under the rate limiter. Prefer offline cracking for a deliberately slow stage. | High. The prior walkthrough presented a command but no viable candidate source and no tested confirmation logic. |
| Cookie policy as clue | The visible authenticated cookie banner links to `/cookie-policy`; that page names `remember_prefs`, `JobTemplate`, and `JobRunner`, but falsely says the two job classes are reserved/not used. It does not show the dangerous state hooks or the result API. | Retain the UI clue if desired, but add a staged hint or a sanitized, target-accessible source artifact explaining that the cookie is deserialized and where child output is retrievable. Avoid asserting a player can infer `__setstate__` semantics from class names alone. | High. Class names suggest an investigation but are not enough to derive the gadget behavior. |
| Web RCE result retrieval | Target source launches commands with stdout/stderr discarded. Output is retrievable only through the bounded one-shot result implementation and an authenticated result route in `web/app/__init__.py`; neither the route nor filename pattern is linked in the UI. The result directory is configured internally. | Put the route and bounded-result design in the same staged source/hint as the pickle clue, or expose a safe non-executing route catalogue in the challenge's public documentation surface. Do not invent that players can browse app source from the target. | Critical. Even if a player guesses command execution, they lack a reliable way to observe its output. |
| Web source accessibility | Web source is copied into a read-only container image. Nginx has no source-download mapping; the IP-only user cannot automatically read organizer repository files. RCE can inspect files after it exists, but that is circular evidence for discovering the first RCE and its output channel. | Publish a sanitized source artifact from the target or add a staged hint that gives enough behavior to reproduce the first Web primitive. Keep source separate from solution scripts. | High. The manual's source-grep steps were organizer-only, not player actions. |
| Access parser | `control/policy.py` is in the Access container, not in the Web image or host runtime allowlist; there is no public source artifact. A player can still black-box test options after discovering the raw DB RPC by comparing order variants and later checking Worker behavior. | Prefer the black-box experiment in `report.md`; if source inspection is a learning objective, publish a sanitized parser artifact at a known, discoverable challenge artifact path. | Medium. Not strictly required if the request-state experiment is exposed, but the old manual's source command was unavailable to players. |
| Raw DB RPC discovery | The normal public Web routes call safe DB operations only. The raw request function is a retained `SECURITY DEFINER` function granted to `relay_web`, and its Python adapter is present in the Web container. It can be discovered after Web RCE by enumerating the app files and inspecting the DB adapter; it is not a public HTTP endpoint. | Keep the present boundary. The report should show filesystem enumeration first and explain why a database call is made only after discovering the adapter. | Moderate. Recoverable after a genuine Web shell; not discoverable from UI before that foothold. |
| Worker ELF artifact | Current workspace `compose.yaml` mounts exactly `/opt/relayforge/bin/relay-worker` read-only into Nginx, and `config/nginx.conf` maps `/artifacts/relay-worker` to that file. This is a local implementation change; no live deployment or matching SHA-256 has been checked. A computed download hash alone is not an independently trusted integrity value. | Redeploy this exact Compose/Nginx change, request the URL from the authorized EC2, verify ELF architecture and compare its digest against an organizer-recorded deployment digest. If possible publish the digest alongside a signed or otherwise trusted manifest. | Critical for binary analysis. Before this route is deployed, an IP-only player has no way to obtain the native ELF; Web RCE does not imply arbitrary host-file access. |
| Artifact URI discovery | The `/artifacts/relay-worker` Nginx location exists in the current workspace but is not linked from the root page or advertised by a current `robots.txt` file. An IP address scan reveals ports, not URL paths. | Publish the path through a public challenge index or `robots.txt`, without exposing organizer-only documents. | High. An artifact route that exists but has no discoverable link still does not solve IP-only discovery. |
| Worker source vs binary | Local `worker/relay-worker.c` and Makefile confirm parser, leak, frame, and shell behavior. The Makefile uses Linux PIE/RELRO/NX flags and does not strip, but the actual served ELF has not been acquired or opened in Ghidra in this validation. | Analyze the exact downloaded ELF in Ghidra and retain screenshots/hash. Treat source as implementation cross-check, not a substitute for deployed binary evidence. | High. Source and deployed build can diverge; claims about actual ELF addresses/layout require analysis of the deployed artifact. |
| Worker port exposure | Supervisor dynamically chooses 25000-25099 and Worker binds `INADDR_ANY`. The local host firewall allows that range only from configured `PLAYER_CIDR`; the cloud security group is separate. Ports are temporary and typically closed before a job exists. | Verify host firewall and AWS security-group rules from a controlled player network. Have the player use the port/token from the authenticated status response and scan that one port while the job is live. | High. An initial full-range scan cannot be expected to reveal a Worker; egress/ingress policy may make it appear filtered. |
| Access-vs-Worker duplicate semantics | `control/policy.py` selects first profile; `worker/relay-worker.c` selects last. `tests/test_policy.py` confirms Access behavior locally. A black-box player should compare accepted/rejected orders, then test `LEAK` on the resulting Worker. No live pair was run. | Preserve two-order controlled tests and a safe-mode negative control. Report request state and Worker command response, not only the inferred parser code. | High. This is the intended cross-component pivot; a one-sided source statement is not sufficient evidence of the live differential. |
| Supervisor socket discovery | The socket is created at `/run/relayforge/supervisor.sock`, mode `0660` with IPC group. It is not mounted into Web; the Worker runtime shares the host filesystem and can inspect it after native shell access. Supervisor checks peer UID, active job, PID cgroup, deadline, exact basename and benign file metadata/content. | Keep the socket clue in Stage 2 marker and demonstrate local enumeration from the earned host Worker shell. Do not suggest Web RCE can reach it. Verify group membership and cgroup behavior on the actual Ubuntu VM. | Moderate. Discoverable after Worker shell; unavailable before then by design. |
| Diagnostic vs archive contradiction | Current Supervisor implements `launch`, `stop`, and `diagnose`; `run_diagnostic` is the vulnerable operation. Snapshot tests explicitly reject retired archive-read code. Any report describing an `archive` operation or flag-reading archive shortcut is stale. | Use only the diagnostic pathname TOCTOU chain. Update any remaining attack guides/report text that mentions archive functionality. | Critical. An archive shortcut changes the final-stage attack and invalidates the intended root-race narrative. |
| Root evidence | Local `tests/test_supervisor.py` replaces the pathname after an acknowledgement in a socketpair harness; it runs the replacement as the test process identity. It does not prove EC2 UID 0. Unit/service source configures the Supervisor as unrestricted root, but the current host deployment was not inspected. | Run a full-chain acceptance only against the disposable, explicitly authorized EC2/VM. Capture `id`, root-only marker access, and flag read; redact the flag. | Critical. Never label local race reachability as verified unrestricted host root. |
| Live screenshots and responses | No Burp captures, Nmap output, Ghidra project, downloaded target ELF, EC2 logs, or live flag output were available for this report. | Collect them during an authorized assessment and mark each capture with timestamp, target, and stage; redact session cookies, credentials, tokens, and flag value. | High. The walkthrough's expected results are source-based, not live observations. |

## Verification Performed Locally

The following checks were run in the workspace and passed:

- `tests/test_policy.py`: production Access parser retains the first profile and accepts the intended differential form.
- `tests/test_pickle_payload.py`: attacker-side payload builder serializes the intended restricted gadget pair.
- `tests/test_supervisor.py`: validation acknowledgement followed by atomic pathname replacement reaches replacement execution in a local socketpair harness.
- `tests/static_audit.py`: intentional-surface and shortcut checks pass, including the Nginx artifact route/mount assertions.
- `docker compose config --quiet`: current Compose syntax parses. It warns that deployment environment values are unset in this local shell; this does not validate an operational stack.
- `git diff --check`: no whitespace errors in the preceding implementation/documentation changes at the time of the check.

None of these checks establishes EC2 reachability, AWS security-group configuration, Hydra recovery, the deployed artifact hash, or a live root flag read.
